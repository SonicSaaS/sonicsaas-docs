# Licensing

**Weight: 15 of 100.**

Microsoft 365 Copilot is an **add-on**. You buy it on top of a subscription you already have, and both
have to be in place before anyone can use it. This area checks that the pieces exist — and flags the
neighbouring licences that decide how much of the rest of this assessment you can actually act on.

A weak score here is rarely a security problem. It is a purchasing conversation.

## Microsoft 365 Copilot licensed [#licensing-copilot-sku]

**What this checks** — whether any Microsoft 365 Copilot licences have been bought for this tenant.

**Why it matters** — nothing about Copilot works without it. This is the add-on itself.

**What "ready" looks like** — at least one Copilot licence present. If there are none, this shows as a
fail, but it does **not** drag down your Readiness score — Readiness is the pre-purchase number and
deliberately ignores whether you own Copilot yet.

**How to fix it** — purchase Microsoft 365 Copilot licences through your Microsoft partner or in the
Microsoft 365 admin centre.

**Microsoft's guidance** — [Microsoft 365 Copilot licence options](https://learn.microsoft.com/en-us/microsoft-365/copilot/microsoft-365-copilot-licensing)

## Copilot seats assigned [#licensing-seats]

**What this checks** — whether the Copilot licences you bought have been given to actual people.

**Why it matters** — an unassigned licence is money spent and not used. Buying seats and never handing
them out is one of the most common ways Copilot spend gets wasted.

**What "ready" looks like** — at least one purchased seat assigned to a user. Like the check above,
this one only counts toward your Full score, not Readiness.

**How to fix it** — in the Microsoft 365 admin centre, go to **Users → Active users**, select a person,
and assign the Microsoft 365 Copilot licence.

**Microsoft's guidance** — [Set up Microsoft 365 Copilot](https://learn.microsoft.com/en-us/copilot/microsoft-365/microsoft-365-copilot-setup)

## Eligible base plan [#licensing-base]

**What this checks** — whether the tenant has a Microsoft subscription that Copilot can be added to.

**Why it matters** — Copilot cannot be bought on its own. Microsoft publishes a list of plans it can be
added to, and it is broader than most people expect: the Microsoft 365 Business and Enterprise plans,
Office 365 plans including E1, the F-series frontline plans, and several standalone plans such as
Teams, Exchange, SharePoint, OneDrive, Visio and Project. There are separate eligible plan lists for
government and education customers.

**What "ready" looks like** — at least one plan from Microsoft's published eligibility list. Most
organisations already have one and simply don't realise Copilot can be added to it.

**How to fix it** — if no eligible plan is present, this is a conversation about which base subscription
suits the organisation, not a setting to change. Note that the plan you hold also affects *which
Copilot* you can buy — Microsoft sells a Business tier alongside the main add-on.

**Microsoft's guidance** — [Microsoft 365 Copilot licence options](https://learn.microsoft.com/en-us/microsoft-365/copilot/microsoft-365-copilot-licensing) lists every eligible plan, including the government and education variants.

## Entra ID P1 or P2 [#licensing-entra-premium]

**What this checks** — whether the tenant has Microsoft Entra ID P1 or P2. (Entra ID is the current name
for what used to be called Azure Active Directory — it is the service that manages sign-ins.)

**Why it matters** — Conditional Access lives in P1 and above. Conditional Access is the feature that
lets you say "require multi-factor authentication for administrators" or "block sign-ins using old
protocols". Several checks in [Identity & Access](/m365/copilot-identity) can only be satisfied
properly if you have it. Without P1, your options there are limited to the free Security Defaults.

**What "ready" looks like** — Entra ID P1 or P2 present, usually because it is bundled in Microsoft 365
Business Premium, E3 or E5.

**How to fix it** — Entra ID P1 comes with Business Premium, E3 and E5. If you have none of those, it
can be bought as a standalone add-on.

**Microsoft's guidance** — [Microsoft Entra ID licensing](https://learn.microsoft.com/en-us/entra/fundamentals/licensing) · [What is Conditional Access?](https://learn.microsoft.com/en-us/entra/identity/conditional-access/overview)

## Purview compliance tier [#licensing-purview]

**What this checks** — whether the tenant has E5-grade compliance licensing (Microsoft Purview).

**Why it matters** — Purview is where sensitivity labels and data loss prevention rules live. The basics
are available at lower tiers, but the capabilities that matter most for Copilot — automatic labelling,
the full data loss prevention feature set, and longer audit retention — are E5-grade features. This
check is not saying you must buy E5. It is telling you which of the recommendations elsewhere in this
report you are currently able to act on.

**What "ready" looks like** — E5-grade compliance licensing present, whether through Microsoft 365 E5 or
the standalone E5 Compliance add-on.

**How to fix it** — if you do not have it, focus on what your current tier *does* allow. Manually applied
sensitivity labels and basic data loss prevention policies are available well below E5 and address most
of the risk. Treat E5 as an option to weigh, not a prerequisite.

**Microsoft's guidance** — [Learn about sensitivity labels](https://learn.microsoft.com/en-us/purview/sensitivity-labels) · [Learn about data loss prevention](https://learn.microsoft.com/en-us/purview/dlp-learn-about-dlp)
